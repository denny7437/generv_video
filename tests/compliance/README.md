# tests/compliance — автотесты правил комплаенса на фикстурах (гейт G1)

Назначение: машинное доказательство гейта **G1** — 100 % правил из
`configs/compliance/rules.yaml` (секции `stop_list` и `platform_extra`) покрыты
автотестами на фикстурах.

## Принцип

- Единственный источник правил — `configs/compliance/rules.yaml`. Список правил
  **не дублируется** ни здесь, ни в скрипте: скрипт читает `id` из `rules.yaml`
  и сверяет с ключами `fixtures.yaml`.
- На каждое правило нужна минимум одна **violating**-фикстура (нарушение) и одна
  **clean**-фикстура (чистая). Правило без фикстур имеет покрытие **0** и роняет гейт.
- Правило с фикстурами, но без маркера `probe`, проверяется только на наличие
  фикстур; с `probe` — дополнительно на то, что нарушение/чистота реальны.

## Файлы

| Файл | Назначение |
|---|---|
| `fixtures.yaml` | фикстуры: на каждое правило `violating[]` + `clean[]` и маркеры `probe[]` |
| `check_coverage.py` | гейт-скрипт покрытия; выполняется в `pnpm verify` |

## Фикстура

Фикстура — текстовый сэмпл, который валидатор стадии [5] увидит на входе:
строка субтитра, оверлей-текст или текстовое описание кадра. Бинарных медиа в git
нет (скилл `hermes-qa-harness`: генерировать на лету).

Схема на правило в `fixtures.yaml`:

```yaml
profanity:
  probe: ["жоп", "сволоч"]        # регистронезависимые подстроки (основы)
  violating:                       # минимум один
    - "Товар — полная жопа"
  clean:                           # минимум один
    - "Кружка керамическая 300 мл"
```

`probe` — маркер(ы), по которым скрипт доказывает, что violating-фикстура
действительно содержит нарушение (хотя бы один маркер), а clean — ни одного.

## Запуск

```bash
python3 tests/compliance/check_coverage.py   # напрямую
pnpm verify                                   # в общем гейте CI
```

## Границы (что явно исключено)

- `product_fidelity` из `rules.yaml` (правило 4.4 «Мы анимируем товар…») — не входит
  в объём G1 (acceptance называет только `stop_list` и `platform_extra`); у него
  отдельная трасса через промпты, валидатор и регламенты.
- `services/worker-qc/src/**` — не трогается: валидатор комплаенса проектируется
  отдельной задачей. Здесь проверяется только **покрытие и осмысленность фикстур**,
  а не сама реализация валидатора.
