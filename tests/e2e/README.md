# tests/e2e

**Пусто. Задача для `hermes-qa`.**

## Критический путь

Один сквозной сценарий, который обязан быть зелёным перед каждым Staging:

```
заказ → бриф → рендер (мок-провайдер) → сборка → QC → выдача
```

## Требования к сценариям (скилл `hermes-qa-harness`)

- Селекторы — по ролям и `data-testid`, не по вёрстке.
- Ожидания — по состоянию; `waitForTimeout` запрещён.
- Фикстуры — из фабрик, не хардкод в тесте.
- Внешние провайдеры — только моки. Живые ключи для тестов не запрашиваются.
- Медиа-фикстуры генерируются ffmpeg (`testsrc`, `sine`) на лету: бинарных роликов в git нет.
- При падении сохраняются трассировка и артефакты.

## Комбинаторика брифа

Бриф многопараметричен: площадка × пресет × длительность × озвучка × язык × число сцен. Полный перебор не нужен — pairwise-набор плюс явные граничные случаи (одна сцена, максимум сцен, максимальная суммарная длительность).
