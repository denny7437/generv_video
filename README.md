# Нейровидео — рекламный ролик автомобиля из 6 фото объявления

Сервис собирает рекламный ролик машины из **шести фотографий объявления о продаже** — по правилам площадок Авто.ру и Авито и по 38-ФЗ «О рекламе», без монтажа, дизайнера и съёмки. Два клиента: B2C-частник (основной по объёму, продаёт одну машину) и B2B-дилер (основной по чеку, десятки машин в месяц).

Репозиторий — **единственный источник истины продукта**: код, контракты, конфиги, ADR. Задачи живут в Linear, приёмку выносит CI.

**Рамка проекта** — `docs/product/{product} {prd} Нейровидео пояснительная записка v2.0 – 2026-08-22.md`. Записка v1.1 от 17.08.2026 **отменена пивотом 22.08.2026** (Linear TEC-54): движок «фото → правдоподобное видео» сохранён, изменены вход, площадки и продукт. Часть кода, конфигов и документов в репозитории всё ещё описывает отменённую рамку — честный перечень в разделе «Наследство отменённой рамки v1.1».

> Продукт — это не генератор видео. Продукт — это машина, которая снижает число попыток на один принятый ролик.

## Быстрый старт

```bash
pnpm install
pnpm verify
```

`pnpm verify` = `lint` + `typecheck` (включая `svelte-check` для `apps/web`) + `test` + `build:web` + `check:oss` + `check:queues` + `check:configs` + `check:compliance` + `check:presets`. Это ровно то, что проверяет пайплайн; локально красное — в CI не отправляем.

```bash
cp .env.example .env && pnpm dev:infra   # postgres, redis, minio в docker compose
pnpm --filter @hermes/api dev            # API на :3000 (fail-fast: без БД и Redis не поднимется)
pnpm --filter @hermes/web dev            # фронтенд (SvelteKit)
```

Отдельно `pnpm check:openapi` линтует контракт — тянет `@redocly/cli@2.46.1` из сети, поэтому в `verify` не входит.

Фактическое состояние на 22.08.2026: тесты — **219 зелёных, 3 пропущено** (34 файла, 1 пропущен), все гейты `verify` проходят. Ни один тест не требует сети, ffmpeg или БД: дорогая логика вынесена в чистые функции (обоснование — `docs/adr/0001`).

## Правила, которые дороже остальных

**Fidelity — главное продуктовое правило (записка §4.4, машиночитаемо в `configs/compliance/rules.yaml` → `product_fidelity`).**

> Мы показываем машину один в один с фото объявления и даём сцене свободу. Максимальная детализация — главный критерий качества: сколы, вмятины, цвет, приборная панель и салон совпадают с исходными фото.

Запрещено досочинять **сам автомобиль**: менять цвет кузова, комплектацию, опции, состояние (сколы, вмятины, царапины, следы эксплуатации), приборную панель и салон, добавлять или убирать элементы машины. Разрешено в **сцене**: нейтральный или новый фон, свет, движение камеры и машины, человек в кадре, смена ракурса в пределах имеющихся фото. Опора — требование Авто.ру «на видео только автомобиль, который вы продаёте» и запрет недостоверной рекламы (ст. 5 38-ФЗ).

**Деньги.** Каждая генерация платная. Идемпотентный ключ, `packages/budget-guard` и различение технического ретрая от перегенерации по запросу пользователя — защита от счёта на порядок больше ожидаемого. Правки `budget-guard`, реестра промптов и конфигов CI — только с апрувом человека.

**Воспроизводимость.** В каждом артефакте и в каждой схеме очереди — `preset_id` и `prompt_registry_version`. Без них жалоба «месяц назад ролики были лучше» не расследуется.

**Open source первым.** Задача не начинается с пустого файла: сначала разведка готовых решений, потом интеграция, и только неизбежный остаток пишем сами. Итог — строка `OSS: <repo@version — reuse | fork | отказ, причина | не применимо>` в отчёте, новая зависимость — строка в `docs/oss-registry.md` и запись в `NOTICE`.

**Площадки** (`configs/platform_specs.yaml` v2.0): Авто.ру — 1 видео на объявление, только по ссылке (Rutube / VK Видео / VK Клипы), фото до 40 шт, jpg, 4:3, ≤ 20 МБ, ≥ 900 px; Авито — mp4/mov/hevc/webm, 5 с – 3 мин (оптимально ≤ 1 мин), ≤ 500 МБ, вертикальное, в категории «Автомобили» нужен тариф; Дром — видео в объявлении не поддерживается. API площадок не используется ни на входе, ни на выходе.

## Связь с Linear

Задачи живут в команде **TEC** (организация TechnologiesAI), проект **Generation Video**. Пивот проведён задачей `TEC-54`.

Агенты ходят в Linear через обёртку (MCP-сервер требует OAuth, недоступного в headless-сессии):

```bash
hermes-linear issue TEC-12
```

Обёртка — часть контура агентов, а не продукта: она живёт в паке контура и попадает в PATH при его установке. В этом репозитории её нет намеренно — здесь только продукт и гейты его CI. Ключ читается из `LINEAR_API_KEY` или `~/.config/hermes/linear.env` (chmod 600); в репозиторий попадают только имена переменных.

Конвенция связи: ветка `task/TEC-<n>-<slug>`, коммит `TEC-<n>: <что сделано>`, один редактируемый комментарий-отчёт на задачу. Ветка вне конвенции роняет job `branch naming` и не связывается с задачей.
