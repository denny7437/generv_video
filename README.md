# Hermes Video Platform

Площадка генерации видео для маркетплейсов. Репозиторий — **единственный источник истины** контура Hermes: код, контракты, ADR, карта репозитория, реестр open source. Задачи живут в Linear, приёмку выносит CI.

## Быстрый старт

```bash
pnpm install
pnpm verify
```

`pnpm verify` = линтер + типы + тесты + сверка реестра OSS + проверка схем очередей. Это ровно то, что проверяет пайплайн; если локально красное — в CI не отправляем. Отдельно `pnpm check:openapi` линтует контракт (тянет линтер из сети).

Локальный стек (postgres, redis, minio):

```bash
cp .env.example .env && pnpm dev:infra
```

API в режиме разработки:

```bash
pnpm --filter @hermes/api dev
```

## Что уже есть

| Модуль | Состояние |
|---|---|
| `packages/domain` | пресеты площадок, ключ идемпотентности платной генерации |
| `packages/budget-guard` | лимиты на job/заказ/сутки, технический ретрай не тарифицируется дважды |
| `services/worker-assembly` | построение команды ffmpeg (чистая функция) + запуск с таймаутом |
| `services/worker-qc` | чек-лист выдачи: формат, длительность, вес, чёрные кадры, тишина, рассинхрон, титры |
| `apps/api` | `POST /orders` с идемпотентностью и проверкой бюджета, `GET /jobs/:id`, `GET /health` |
| `contracts/` | OpenAPI, схема БД + миграция, четыре схемы очередей, интерфейс видео-провайдера |

51 тест, все зелёные. Ни один не требует сети, ffmpeg или БД — вся дорогая логика вынесена в чистые функции (обоснование: `docs/adr/0001`).

## Чего нет намеренно

`apps/web`, `services/worker-script`, `services/worker-render`, `tests/e2e`, боевое хранилище вместо памяти в `apps/api`. Это первые задачи для `hermes-dev` — см. `docs/repo-map.md`, колонка «Состояние».

## Правила, зашитые в CI

| Гейт | Что ломается при нарушении |
|---|---|
| `pnpm check:oss` | production-зависимость отсутствует в `docs/oss-registry.md` — правило «open source первым» не выполнено |
| `pnpm check:queues` | в схеме очереди нет `idempotency_key`, `cost_estimate`, `attempt_policy`, `preset_id`, `prompt_registry_version`, `trace_id` |
| `pnpm check:openapi` | контракт невалиден (версия линтера пината в `redocly.yaml` и в пайплайне) |
| branch naming | ветка не по конвенции `task/TEC-<id>-<slug>` — Linear не свяжет её с задачей |

## Два правила, которые дороже остальных

**Деньги.** Каждая генерация платная. Идемпотентный ключ, `budget-guard` и различение технического ретрая от перегенерации по запросу пользователя — защита от счёта на порядок больше ожидаемого. Правки `packages/budget-guard` агентам запрещены без апрува человека.

**Воспроизводимость.** В каждом артефакте — `preset_id` и `prompt_registry_version`. Без них жалоба «месяц назад ролики были лучше» не расследуется.

## Пресеты площадок не подтверждены

Все пресеты в `packages/domain/src/presets.ts` помечены `verified: false`: значения длительности, веса и безопасных полей — рабочие заглушки, а не требования маркетплейсов. Их нужно сверить с официальной документацией площадок и подтвердить. До этого `assertPresetUsable()` не пропускает пресет на боевую выдачу, а API отвечает `409 preset_not_verified` при `NODE_ENV=production`.

## Связь с Linear

Задачи живут в команде **TEC** (организация TechnologiesAI), проект **Generation Video**. Пилотный эпик — `TEC-5`.

Агенты ходят в Linear через обёртку (MCP-сервер требует OAuth, недоступного в headless-сессии):

```bash
hermes-linear issue TEC-12
```

Сама обёртка — часть контура агентов, а не продукта: она живёт в паке (`Hermes видеоплатформа – …/scripts/linear.sh`) и попадает в PATH как `hermes-linear` при установке контура (`install.sh`). В этом репозитории её нет намеренно — здесь только продукт и гейты его CI.

Ключ читается из `LINEAR_API_KEY` или `~/.config/hermes/linear.env` (chmod 600). В репозитории — только имя переменной; значения секретов сюда не попадают.

Конвенция связи: ветка `task/TEC-<n>-<slug>`, коммит `TEC-<n>: <что сделано>`. Ветка вне конвенции роняет job `branch naming` в CI и не связывается с задачей.
