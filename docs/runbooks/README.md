# Runbooks

Формат секции — фиксированный. Симптом → диагностика → действие → откат → когда звать человека. Заполняет `hermes-devops` в той же задаче, где появляется новая очередь, сервис или алерт.

```
## <Симптом>
Как проявляется: <что видно в дашборде или алерте>
Диагностика: <команды, где смотреть>
Действие: <шаги>
Откат: <одна команда>
Эскалация: <когда звать человека>
```

---

## Локальный стек не поднимается

Как проявляется: `pnpm dev:infra` завершается ошибкой, порты 5432/6379/9000 заняты.
Диагностика: `docker compose -f infra/docker-compose.yml ps`, `lsof -i :5432`.
Действие: остановить конфликтующий процесс либо переопределить порты в `.env`.
Откат: `pnpm dev:infra:down`.
Эскалация: не требуется.

## Заготовки — заполняются при появлении соответствующих сущностей

Пустые секции оставлены намеренно: они показывают, чего в контуре ещё нет, и превращаются в задачи.

- **DLQ растёт** — появится вместе с первой очередью BullMQ.
- **Job рендера висит дольше таймаута** — появится вместе с `services/worker-render`.
- **Расход бюджета провайдера за час выше нормы** — появится вместе с боевым адаптером провайдера.
- **Смоук после деплоя красный** — появится вместе с пайплайном staging.
- **Бакет артефактов растёт быстрее плана** — появится вместе с политикой жизненного цикла S3.

Правило: алерт без секции в runbook считается незавершённой задачей.
