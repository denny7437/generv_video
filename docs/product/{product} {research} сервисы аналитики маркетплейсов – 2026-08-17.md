# Сервисы аналитики маркетплейсов — выбор источника данных для playbook и golden set — 2026-08-17

**Задача:** TEC-36 · **Роль:** hermes-product (A-11/A-10) · **Дата проверки фактов:** 2026-08-17
**Решение владельца (TEC-35):** источник данных для A-11 и golden set — сервис аналитики маркетплейсов; hermes-product выбирает лучший по данным. Решение и оплата — Денис.

---

## 1. Что нам нужно от источника (критерии — из acceptance TEC-36)

Зависимые задачи: **TEC-28** (playbook — параметризованные шаблоны сценариев, ≥ 30 топовых карточек на категорию) и **TEC-31** (golden set — 60+ SKU с исходными фото), через них — ручной замер TEC-32 и весь гейт G1.

| # | Критерий | Зачем |
|---|---|---|
| 1 | Топ карточек по категориям Ozon: Одежда, Дом и сад, Электроника | TEC-28: A-11 не начинает работу без выборки ≥ 30 топ-карточек на категорию |
| 2 | Доступ к фото/медиа карточек | playbook (анализ приёмов) и golden set (исходные фото) |
| 3 | Выгрузка ≥ 30 карточек на категорию | покрытие выборки A-11 за один проход |
| 4 | Наличие API | автоматизация сбора вместо ручного экспорта |
| 5 | Глубина атрибутов карточки | что размечаем: цена, продажи, рейтинг, изображения, атрибуты |
| 6 | Тариф (ссылка + дата), лимиты выгрузки, пробный период | себестоимость сбора данных |
| 7 | Юридически: ToS/оферта допускает использование выгрузок для нашей цели | риск переиспользования данных |
| 8 | Закрывает ли потребность golden set (исходные фото) или нужен второй источник | граница решения по вопросу 7 записки |

## 3. Детально по сервисам

### 3.1 MPStats — https://mpstats.io  ← рекомендация

Лидер рынка аналитики WB/Ozon/Яндекс Маркет/Авито. Проект уже опирается на MPStats: пояснительная записка (Приложение Б) цитирует `mpstats.io`, а правило входа A-11 сформулировано как «без MPStats либо ручной выборки ≥ 30 карточек на категорию не начинает работу».

Проверено напрямую 2026-08-17:

- **Покрытие Ozon — подтверждено.** В JS-бандле SPA видны модули `client_oz: "Ozon: внешняя аналитика"`, маршруты `ozon/category → products` (топ товаров по категории), `top-sellers`, `top-brands`, `item/:sku` (карточка товара), «Сравнение WB+Ozon» (модуль «Выбор ниши»), репрайсер Ozon. Источник: `https://mpstats.io/` (SPA, бандл `/assets-spa/CTYBdmZs.js`).
- **API — подтверждён и живой.** Базовый endpoint `https://mpstats.io/api` отвечает HTTP 405 (метод не разрешён для GET) — признак живого бэкенда. Авторизация — токен из личного кабинета (Настройки → Интеграции → Создать токен). API отдаёт товары по категории с пагинацией (100/страницу), сортировкой и фильтрами по выручке — метод `getSubjects(categoryId)`. Источник: README OSS-клиента `bellenne/mpstats-php-client` (MIT) — https://github.com/bellenne/mpstats-php-client.
- **Покрытие Ozon через API — подтверждено.** OSS-фреймворк `vibe-commerce/vibecommerce_ai_analyst_code` описывает себя как «niche analysis (Ozon via MPStats API)». https://github.com/vibe-commerce/vibecommerce_ai_analyst_code.
- **Тарифы** — НЕ ПРОВЕРЕНО: страница `https://mpstats.io/tariffs` (HTTP 200) — SPA, цены подгружаются JS, в статическом HTML их нет; API-доки (`/docs`) за логином.

## 4. Юридическая проверка (acceptance)

Требование: ToS/оферта должна допускать использование выгрузок для построения playbook и golden set.

- Moneyplace: оферта найдена, но говорит об остановке продаж — сервис выбывает независимо от пунктов ToS.
- Остальные: ToS/оферта — НЕ ПРОВЕРЕНО (частично за логином, частично SPA).

**Риск, который надо закрыть до гейта G1, а не принять молча:** аналитические сервисы лицензируют *доступ* к своим данным, но не обязательно право *переиспользовать* их для построения сторонней базы/шаблонов. Пункт «аналитическое использование выгрузок для собственных продуктовых шаблонов» должен быть либо явно разрешён ToS, либо отдельно решён Денисом (в т.ч. юристом).

## 5. Golden set: закрывает ли источник потребность в исходных фото?

Различие принципиально:

- **Playbook (TEC-28)** — топ-карточки: их фото и атрибуты аналитический сервис отдаёт из публичных витрин. MPStats закрывает.
- **Golden set (TEC-31)** — 60+ SKU с исходными фото, которыми мы сами управляем (права на использование, воспроизводимость, эталонная разметка A-36). Аналитический сервис может отдать фото, но не гарантирует право переиспользовать их как эталонный набор.

**Вывод:** аналитика закрывает playbook; для golden set с высокой вероятностью нужен второй источник — собственные SKU/исходники от Дениса (пилотные аккаунты селлеров, свои товары). Это ровно формулировка вопроса 7 записки: исходники golden set и пилотные аккаунты — за человеком (§7.6).

## 7. Рекомендация

**«Самый крутой по данным» — MPStats (https://mpstats.io).**

Основание (только подтверждённые факты, 2026-08-17):

1. **Единственный с подтверждённым живым API** (`/api` отвечает, токен из ЛК, пагинация 100/стр., фильтры по выручке) — критерий № 4 закрыт безусловно, автоматизация сбора для TEC-28/TEC-31 возможна без ручного экспорта.
2. **Покрытие Ozon подтверждено** — модуль «Ozon: внешняя аналитика», категория → топ товаров, продавцы, бренды, карточка `item/:sku` с медиа. Критерии № 1–3 закрываются.
3. **Лидер рынка** и уже эталон в записке (A-11): переключение на MPStats не вводит нового риска, а снимает существующий.
4. **Конкуренты выбыли по фактам:** Moneyplace остановил продажи (оферта), Stat4Market недоступен (redirect-цикл). Поле сузилось до MPStats / MarketGuru / Маяк, и ни у одного из оставшихся кандидатов API не подтверждён так же, как у MPStats.

**Цена: НЕ ПРОВЕРЕНО** — тарифная страница MPStats грузит цены через JS и за логином, автоматически цену не вытащить. Это единственный незакрытый пункт acceptance № 2/5. **Нужно от Дениса:** войти в `https://mpstats.io/tariffs`, зафиксировать актуальный тариф и лимиты выгрузки (и/или пробный период) — тогда цифра появится с URL и датой.

Рекомендация по выбору сервиса — **MPStats**. Решение и оплата — Денис.
