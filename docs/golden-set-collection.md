# Требования к датасету (golden set): реклама автомобилей из 6 фото

> Составлено hermes-lead (A-00) 2026-08-22. Основание: записка v2.0 §5.2, §6 (G1), §7.6;
> `configs/mvp_scope.yaml` v2.0 (типы кузова); эскалация TEC-58.
> Документ отвечает на один вопрос: **что именно собрать, в каком виде и как проверить.**
> Исходники — входные данные человека (§7.6); разметку `golden_set/labels/` делает только qa (A-36).

## 0. Два объёма — читай по назначению

| Уровень | Назначение | Объём |
|---|---|---|
| **1 — тест** | ручной замер числа попыток (гейт G1: ≤ 2,2 на 10–15 машинах) | **10–15 машин** |
| **2 — полный** | эталон для метрик «попытки/покрытие» (гейты G1–G2) | **≥ 60 машин** |

Уровень 1 — подмножество уровня 2: машины, собранные для теста, переиспользуются в полном наборе.
Начни с уровня 1 — этого достаточно, чтобы запустить тест.

## 1. Что такое одна единица датасета

Одна единица = **один конкретный автомобиль**. По каждой машине нужны:

1. **6 фото** (ровно столько — это вход нашего продукта), из объявления о продаже:
   - общий вид (3/4 спереди или сбоку),
   - задний ракурс,
   - **салон / приборная панель**,
   - крупный план детали (диск, фара, эмблема, кнопки),
   - + любые 2 из: багажник, моторный отсек, другой ракурс кузова.
2. **Ссылка на объявление** (Авто.ру или Авито) — оттуда qa возьмёт контекст.
3. **Атрибуты:** марка, модель, год, **тип кузова** (см. §2), цвет кузова, пробег (если известен).

## 2. Типы кузова (из `configs/mvp_scope.yaml`, не менять)

| id | Что входит | Доля (ориентир) |
|---|---|---|
| `sedan_hatch` | седан / лифтбек / хэтчбек | ~1/3 |
| `crossover_suv` | кроссоверы и SUV | ~1/3 |
| `business_premium` | бизнес и премиум (BMW/Mercedes/Audi/Lexus и т.п.) | ~1/3 |

Уровень 1: по **4–5 машин на каждый тип**. Уровень 2: ~20 на тип.

## 3. Требования к фото

- [ ] Фото **этой конкретной машины** из объявления — не сток, не другая машина.
- [ ] **Без водяных знаков, логотипов, цен, скидок, контактов** — это стоп-лист
      (`configs/compliance/rules.yaml`).
- [ ] Машина в фокусе, читаемая приборная панель; резкость достаточная, чтобы
      были видны детали и состояние.
- [ ] Разрешение ≥ 900 px по длинной стороне, формат jpg (требование Авто.ру).
- [ ] **Состояние показываем как есть:** сколы, вмятины, царапины, следы эксплуатации
      **не ретушировать и не скрывать** — правило fidelity «машина один в один с фото»
      (записка §4.4). Если на машине есть дефекты — они должны быть видны на фото,
      ролик обязан их сохранить.
- [ ] **Права на использование.** Только объявления, где у тебя есть право использовать
      фото: свои машины, машины знакомых/партнёров с их согласием, фото дилера по
      договорённости. Чужие объявления скрейпом брать нельзя (ToS площадок, ПДн на
      госномерах, авторские права продавцов) — это причина эскалации TEC-58.

## 4. Формат сдачи

Папка с фото, разложенная по типам кузова, + таблица-манифест:

```
golden_set/
  source/
    sedan_hatch/
      car-001/ 1.jpg 2.jpg 3.jpg 4.jpg 5.jpg 6.jpg
      car-002/ ...
    crossover_suv/
      car-003/ ...
    business_premium/
      car-004/ ...
  manifest.csv
```

`manifest.csv` — колонки (порядок не важен):

```csv
car_id,platform,card_url,body_type,brand,model,year,color,photo_count
car-001,autoru,https://auto.ru/cars/used/sale/...,sedan_hatch,Kia,Rio,2021,белый,6
```

Правила `car_id`: уникальный, стабильный, латиница/цифры/дефис (`car-001`).
**Сдача = папка `golden_set/source/` + `manifest.csv`** (архив zip тоже ок — qa разложит).

## 5. Критерий «ролик принят» (нужна твоя формулировка)

Для разметки qa нужно от тебя по каждому типу кузова 1–2 фразы, что значит
«ролик соответствует машине и проходит». Примеры (поправь своими словами):

- **Седан/хэтчбек:** та же модель/цвет/диски, что на фото; дефекты кузова видны, не замазаны.
- **Кроссовер/SUV:** кузов, клиренс, оптика совпадают с фото; ничего не добавлено в кадр.
- **Бизнес/премиум:** приборная панель, салон, эмблемы — один в один с фото.

Технический критерий уже задан системой: «принятый = прошёл автовалидацию **и**
совпал с эталонной разметкой» (§5.2) — от тебя нужен именно эталон формулировки.

## 6. Как проверить, что собрано правильно

- [ ] Уровень 1: 10–15 машин, в каждом типе кузова ≥ 4; у каждой 6 фото + ссылка + атрибуты.
- [ ] Уровень 2: ≥ 60 машин, в каждом типе ≥ 18.
- [ ] Ссылки ведут на живые объявления Авто.ру/Авито.
- [ ] На фото нет водяных знаков/цен/контактов.
- [ ] `manifest.csv` полный, `car_id` уникальны, `body_type` ∈ {sedan_hatch, crossover_suv, business_premium}.
- [ ] Критерий «ролик принят» задан для всех трёх типов (§5).

## 7. Что делает qa после сдачи (не твоя забота)

Разложит фото в `golden_set/source/`, проверит стоп-лист, сверит manifest,
сформирует отложенную часть (holdout ≥ 20 % и ≥ 30 единиц, недоступна разработке)
и — после твоего критерия из §5 — эталонную разметку `golden_set/labels/`.

---

## Чек-лист сдачи (уровень 1, для теста)

1. Выбрать 10–15 машин (по 4–5 на тип кузова), фото которых можешь использовать.
2. Скачать по 6 фото каждой в `golden_set/source/<body_type>/<car_id>/`.
3. Заполнить `manifest.csv`.
4. Написать критерий «ролик принят» по трём типам (§5).
5. Сказать «готово» — qa примет, и запустим ручной замер.
