# Карта репозитория

По этой карте агенты решают, какие файлы читать. Репозиторий целиком не сканируется — карта отстала, значит все агенты тратят бюджет впустую. Поддерживает `hermes-writer` после каждого merge, меняющего структуру.

## Раскладка

| Путь | Назначение | Публичный интерфейс | Фаза | Состояние |
|---|---|---|---|---|
| `apps/api` | HTTP-слой: заказы, статусы job | `contracts/openapi/api.yaml` | E1–E3, E7 | скелет: хранилище в памяти, очередей нет, `bearerAuth` объявлен в контракте, но не проверяется |
| `apps/web` | фронтенд: кабинет, бриф, медиатека, превью | — | E1–E3, E7 | **пусто**, первая задача |
| `packages/domain` | доменные типы, пресеты площадок, ключ идемпотентности | — | все | готово |
| `packages/budget-guard` | лимиты расхода на генерации (**правки только с апрувом человека**) | — | все | готово |
| `services/worker-assembly` | построение и запуск команды ffmpeg | `contracts/queues/assembly.json` | E6 | чистая логика готова, подписка на очередь — задача |
| `services/worker-qc` | автоматический видео-QC перед выдачей | `contracts/queues/qc.json` | E7 | чистая логика готова, ffprobe-пробник — задача |
| `services/worker-script` | бриф → сценарий, реестр промптов | `contracts/queues/script.json` | E4 | **не создан** |
| `services/worker-render` | вызов провайдеров генерации | `contracts/queues/render.json` | E5 | **не создан** |
| `contracts/` | OpenAPI, схема БД и миграции, схемы job, интерфейс провайдера | сам является интерфейсом | все | посевной набор |
| `infra/` | локальный стек (compose); чарты и пайплайн деплоя | — | — | только compose |
| `scripts/` | только гейты CI: реестр OSS, схемы очередей, конфиги | `pnpm check:oss`, `check:queues`, `check:configs` | — | готово |
| `tests/e2e` | Playwright: заказ → бриф → рендер (мок) → QC → выдача | — | все | **пусто**, задача |
| `docs/` | ADR, runbooks, эта карта, реестр OSS | — | — | — |

## Чего в этом репозитории нет намеренно

Здесь лежит **только продукт**: код, контракты, документация продукта и гейты его CI. Инструменты контура агентов — обёртка Linear (`linear.sh` → команда `hermes-linear` в PATH), мост `Linear → доска исполнения` (`linear-sync.py`), мост Open WebUI (`webui-bridge.py`, `openwebui-pipe.py`) и отдельный Chrome для агентов (`chrome-agent.sh`) — живут в паке контура: `$HERMES_VIDEO_PACK/scripts/` (по умолчанию `~/Desktop/Hermes видеоплатформа – 2026-08-16`). Точка входа человека — `gv`.

Граница простая: если файл нужен, чтобы **строить и проверять продукт** — он здесь; если чтобы **запускать агентов, которые его строят** — он в паке. Скрипт контура, оказавшийся в `scripts/`, не попадает ни в `pnpm verify`, ни в CI, и живёт непроверенным — так и вышло с этими пятью.

## Зависимости между модулями

```
apps/web ──▶ apps/api ──▶ [очереди BullMQ] ──▶ worker-script ──▶ worker-render ──▶ worker-assembly ──▶ worker-qc ──▶ S3
                 │                                                                                          │
                 └──────────────────────── packages/domain, packages/budget-guard ───────────────────────────┘
```

Правила, за нарушение которых ревью возвращает PR:

- воркеры не ходят в БД мимо `packages/domain`;
- фронтенд не знает о провайдерах генерации;
- провайдер-специфика не покидает `services/worker-render`;
- решение «генерация оплачивается» принимается только в `packages/budget-guard`.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm verify` | всё, что проверяет CI: линтер, типы, тесты, реестр OSS, схемы очередей |
| `pnpm test` | тесты (vitest) |
| `pnpm typecheck` | типы без сборки |
| `pnpm dev:infra` | поднять postgres/redis/minio локально |
| `pnpm check:oss` | сверка зависимостей с `docs/oss-registry.md` |
| `pnpm check:queues` | обязательный минимум полей в схемах очередей |
| `pnpm check:openapi` | линт контракта (тянет `@redocly/cli` из сети) |

Имя `ci` для скрипта занято самим pnpm — поэтому агрегирующая команда называется `verify`.

## Как поддерживать

1. Новый модуль → строка в таблице + стрелка в схеме.
2. Изменился публичный интерфейс → обновить колонку.
3. Модуль удалён → строка удаляется в том же PR, а не «потом».
4. Колонка «Состояние» — не украшение: по ней `hermes-lead` понимает, что можно делегировать, а что ещё не существует.
